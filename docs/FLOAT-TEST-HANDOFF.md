## 测试入口

角色应用：NPC → 手动填写；批量导入 → 粘贴资料、选择 API、解析并预览；角色详情 → EDIT → 角色身份。

角色背景编辑合并旧 persona 和 personality，保存时把正文写入 persona，清空旧 personality，避免重复注入。旧字段仍保留类型兼容性。配角身份沿用原系统 tags 的“配角”标签，切换不会重建角色 ID、删除聊天或关系，也不会自动更改朋友圈发帖开关。

原系统生成的配角本身就是完整角色卡；生成时额外建立双向关系并默认关闭自动发朋友圈。“朋友圈路人 NPC”是另一类临时作者身份，不能当作已建档配角转换。

## 批量导入

通过用户选择的模型 API 提取姓名、统一背景、世界与主配角建议；预览阶段不写角色存储。确认时检测重名，不覆盖已有角色。导入的具名世界新建为“世界名（导入）”，空世界归入当前世界。不自动推断并写入关系连线，原资料里的关系先保留在背景中。

## 其他设备接手

## 人物资料注入设置

在世界画布点击两人之间的关系线，分别设置“A了解B”和“B了解A”。范围：现有简介、完整角色背景、自定义可知资料；时机：始终、关键词、不注入人物资料。关键词按最近6条聊天文本匹配，逗号等分隔、任意命中、英文不区分大小写；不递归扫描注入文本。默认沿用简介始终注入。不注入仅针对人物资料，不隐藏关系线、姓名或世界描述；完整背景可能包含角色秘密。设置由当前世界按观察者与被观察者保存，仍需启用预设角色关系标记。改变设置不会清除旧聊天、记忆中已经出现的信息。新规则当前接入中央私聊与群聊提示组装，不应宣称覆盖所有独立辅助任务。

原版仓库 kirakira001/ai-virtual-phone-personal 只按用户要求引入 xiaolongbao0709/ai-virtual-phone 的更新，不混入本测试分支。更新前对比数据库名称、键名、Dexie version/upgrade、清空/删除数据库调用、导入导出及迁移脚本；有破坏性迁移时先报告，不直接上线。保留原站 HTTPS 域名、协议和端口，保留用户 Safari 网站数据。不能声称同域更新永远无数据风险，也不能把回滚代码当作数据库备份。

浏览器角色和设置使用 AiPhoneKvDB 的 entries 表，角色键 ai_phone_characters_v1；聊天有单独 IndexedDB 数据库。Vercel 更新代码通常不直接清除 Safari IndexedDB，但上游迁移、用户清除网站数据、浏览器回收及设备丢失仍可能造成数据丢失。需要有可恢复的备份后才可承诺恢复能力；若用户不便操作备份，先研究自动备份方式，不要求其为测试副本搬迁数据。

原版和测试版必须使用不同 HTTPS 域名，使浏览器存储按 origin 隔离。测试版新域名从空白开始，不读取、共享或同步原版用户数据。不向原版提交我们的功能改动；不把测试域名指向原站，也不将原域名改为测试部署。

个人角色、聊天和 API 配置保存在浏览器 IndexedDB，不是 GitHub 中的代码资料。永远不要提交用户导出、密钥、Token 或 .env 实际值。
